# 05 — YC application and proof plan

## Critical YC video rule (official)
YC founder application video: **one minute, founders talking, no promotional demo in that video**. Product demo is submitted separately. Source: https://www.ycombinator.com/video . Winter 2027 on-time deadline listed as November 2, 2026, 8pm PT at https://www.ycombinator.com/apply (verify live before submitting).

## What the product demo must prove
1. **Cross-assistant entry:** owner types natural-language request in one connected assistant.
2. **Knowledge & automation discovery:** Gluons recommends a relevant expert-curated skill and transparently displays data sources and risk.
3. **Owner control:** owner activates a trial with known budget and approval policy.
4. **Real verified system work:** a source message becomes a validated order draft in a real authorized ERP sandbox, with a visible external receipt.
5. **Durability:** task remains active after leaving the chat, status continues in Gluons dashboard.
6. **Cross-workflow orchestration:** a separate follow-up/exception workflow is triggered by a real outcome, not a hard-coded prerecorded transition.
7. **Second channel:** ElevenLabs phone call uses real phone/voice and calls Gluons authorized tool; show it querying legitimate business data and writing a sandbox order/reservation after approval.
8. **Trust:** owner pauses/cancels, sees external effects and cost ledger; risky request is blocked by platform policy.
9. **ROI:** show observed data only or synthetic sandbox data clearly labeled as such.

## What must be real vs can be simulated
- **Real:** OAuth permission on test account, remote MCP call, one live external API sandbox write and readback, ElevenLabs phone event, persistent task state, real human approval, model-route decision and cancellation, accurate metering.
- **May be synthetic if labeled:** fictional customer business, sample orders, projected ROI, names, legacy ERP responses, mock courier events, customer testimonials (better exclude entirely).
- **Never imply:** 31 production integrations exist merely because 31 skills are written; one simulated demo is equivalent to signed customers; an LLM-reported success means actual system success; trial results predict guaranteed revenue.

- Interview **30–50** owners across wholesale/distribution, property management, and service companies, recording prior automation use, sentiment and exact workflow pain, no leading questions.

## Strong YC application answers to prepare
- What are you building? One-sentence description and one concrete example with verified output.
- Who needs it most? Named operational personas and interviews, not 'all SMBs'.
- Why do you know this problem? Founder access to businesses, personal experience and prototype results.
- Why this isn't just Zapier + Claude? Domain-reviewed procedures, enduring task state, unified policy, owner control, shadow trials, measurable task results.
- What is novel/technical? Durable state model, provider-agnostic execution, skill validation, approval separation and cross-host controls.
- How do you make money? Base platform access + consumption + optional human setup; measured COGS and vendor pass-through.
- Biggest risks? Partner-specific connectors, regulatory constraints, marginal economics of handholding, platform permission limits, reliability under long workflows.
- What is live today? State every live component accurately.

## High-quality demo recording hygiene
Record browser, app, API receipt and inbound call using an authorized test number with permission. Remove customer secrets, phone numbers, access tokens, medical/legal data and private chats. Avoid jump cuts that hide failures in a purported live trace; include clear segmentation if the video is edited. Verify all outgoing links before application submission.
